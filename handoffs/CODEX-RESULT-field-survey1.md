## 2. Job record and stores

- **Common snapshot:** `snapshotState`, `index.html:1014`, returns keys `app`, `schemaVersion`, `appVersion`, `savedAt`, `jobId`, `siteUpcharges` ({demo,slope,urban,hardDig}), `laborHours`, `projectName`, `jobCustomer`, `jobAddress`, `jobNotes`, `elements`, `labels`, `materials`, `specs`, `showCostView`, `pan`, `zoom`, `snapFt`, `costs`, `labor`, `markup`, `footing`, `postODIn`, `postEmbedIn`, `autoPost`, `postSpacing`, `underlay`, `quote`. Specs/addons are serialized; elements serialize specs/runSpecs. Job inputs come from `readJobPricingInputs`, `index.html:989`.
- **Saved Jobs:** Save handler in `updateDrawers`, `index.html:3158`, deep-clones snapshot, adds `id` and `name`, replaces savedAt with locale string, updates S.savedJobs and writes its JSON array to STORAGE_KEY (`index.html:3171`). Saved load deep-clones and calls applyState (`index.html:3182`); Delete persists at `index.html:3193`. `ensureSavedJobIds`, `index.html:1001`, backfills missing ids and writes at `index.html:1012`; boot reads at `index.html:3583`.
- **Identity:** live `S.jobId` starts null (`index.html:1320`), loads from st.jobId else st.id (`index.html:1038`). Save allocates Date.now (`index.html:3170`); name collision can reset identity (`index.html:3162`). In particular, a rename to a name absent from the list makes !sameName true and allocates a new id. This is a local record link, not a UUID or guaranteed cross-device/rename identity. Legacy backfill avoids collisions within the existing list; regular Save uses a timestamp without that loop. Backup merge uses names, not ids (`index.html:4722`). Clear resets jobId (`index.html:3817`).
- **Autosave:** `saveSession`, `index.html:1096`, writes snapshot JSON to AUTOSAVE_KEY; debounce 1 s, periodic 20 s, pagehide/hidden triggers (`index.html:1097`). Boot restores with applyState only when hasContent passes (`index.html:3593`); an isolated future actuals field would not itself satisfy today's predicate.
- **Portable job export:** inline do-export handler, `index.html:3144`, serializes snapshot to .fencebound.json, optionally adds exportWarning when validation fails. No distinct portable schema. Import handler, `index.html:3770`, checks app + elements array, calls applyState (`index.html:3782`), clears history/future, renders, writes autosave directly (`index.html:3787`), restores prior S/pricing/inputs on failure. Import does not directly create a Saved Jobs record.
- **Full backup (distinct from portable job):** `exportBackup`, `index.html:4650`, emits `{format,app,appVersion,exportedAt,jobs,pricing,pricingIncluded,company}`; jobs is the saved array, not unsaved live job. Pricing is the saved company card. `openRestoreDialog`, `index.html:4669`, optionally merges/replaces jobs and writes STORAGE_KEY (`index.html:4723`); company/card restores are separately selected actions. handleBackupFile at `index.html:4754` validates the outer payload, not every job field.
- **Quote:** runtime `S.quote` = `{frozenAt,total,pricing,signature?}`. `pricing=clonePricing()` contains costs/labor/markup/footing/postODIn/postEmbedIn (`index.html:1635`). First successful estimate PDF export freezes it, subsequent exports retain pricing and refresh total (`index.html:5527`). Signature `{image,name,signedAt,total}` is accepted at `index.html:4620` and sanitized at `index.html:1627`.
- **Quote persistence asymmetry:** snapshot flattens current pricing into top-level costs…postEmbedIn and serializes only quote frozenAt/total/signature (`index.html:1020`). applyState reconstructs quote.pricing from those top-level values (`index.html:1047`). `writeQuoteToSavedJob`, `index.html:4584`, instead deep-copies the full runtime quote (including pricing) into the matching existing record without updating its top-level pricing or other edits. Thus rec.quote.pricing may exist, but applyState reads top-level pricing, not that nested object. A never-saved job gets no record from this helper. This is observed source behavior, not a tested defect claim.
- **Company card:** `saveCostDB`, `index.html:1809`, writes only costs/labor/markup/footing/postODIn/postEmbedIn to COSTDB_KEY and refuses while _pricingFromLoadedProject. readSavedCostDB/mergeSavedCostDB at `index.html:1733` / `index.html:1742`; profile has a separate key/saveCompany (`index.html:4542`, `index.html:4557`). No actuals field or actual-cost store exists in these paths.

## 3. Actuals attachment points — options, no recommendation

| Possible location | Serialization/load consequences and boundary |
|---|---|
| Job-level S.actuals / snapshot.actuals, sibling of quote | Would require S initialization/reset, explicit snapshotState emission (`index.html:1014`), applyState validation + missing-field reset (`index.html:1027`), and inclusion in the boot content rule if actuals-only sessions should restore (`index.html:3593`). Existing Saved Jobs/portable/autosave serializers share this snapshot; import rollback captures S via spread (`index.html:3775`), so nested mutation/cloning would need review. Backup transports saved records verbatim. No company-card write is needed. |
| Saved Jobs record.actuals only | Raw backup jobs would carry it; applyState currently ignores unknown top-level keys and Save rebuilds the record from snapshot, dropping it (`index.html:3171`). Live editing, Save preservation, portable export and current-session autosave would need explicit handling. A helper analogous to writeQuoteToSavedJob could write it independently, but never-saved jobs, rename/id behavior and delete/restore need specified semantics. |
| Separate actuals store keyed by job id | No existing key/helper for this. Would require separate serializer/sanitizer plus Save/load/reset/import/export/backup/restore/delete links; stable identity/collision policy is relevant (§2). Existing backup captures only known stores (`index.html:4654`), so it would omit this store today. Company card can remain untouched. |
| Nested quote.actuals | Both snapshotState and applyState rebuild a restricted quote and would discard an unknown field (`index.html:1025`, `index.html:1058`); writeQuoteToSavedJob copies runtime quote, but export also rebuilds it (`index.html:5530`). Re-price/Clear drop quote (`index.html:3735`, `index.html:3817`). These lifecycle consequences differ from job-level data. |

All options need an actuals-specific field/number/unit/size validator; none exists. `sanitizePricingInputs` (`index.html:1698`) validates estimate rates, not receipts, actual hours or installed quantities. Portable import's shallow outer check is not such a validator. Saved loads/autosave/portable imports converge on applyState; raw backup restoration bypasses it until a job is loaded. `sanitizeSignature` and `sanitizeUnderlay` are separate image boundaries, not generic attachment validators.

Company isolation facts: applyState starts from the company card, layers quoted-job prices only into working globals, and never writes the card (`index.html:1041`); useCompanyRateCard reads saved card (`index.html:1638`); saveCostDB has provenance guard (`index.html:1810`). The owner's local-first 6b split is recorded at `Docs/development/DEVELOPER_LOG.md:1086`. Actual quantities/costs and hours would be job evidence, not additions to COST_DB/LABOR/clonePricing. No ranking or schema is selected here. Drawing history contains only elements/labels (`index.html:2335`), so none of these locations automatically participates in undo.
